# Работа с саб-агентами

Этот документ описывает, как ускорять разработку `Prince of Hell` параллельной работой до трёх саб-агентов без потери качества и контекста.

## Принцип

Главный агент — технический владелец задачи: принимает архитектурные решения, назначает границы работы, интегрирует результат, запускает итоговую проверку и коммитит. Саб-агент получает только независимую, конечную подзадачу с измеримым результатом.

Не запускать саб-агента для разговора, размышлений без артефакта, задачи на 5 минут или последовательного шага, который зависит от незавершённого результата другого агента.

## Роли и модели

| Роль | Рекомендуемая модель | Подходящие задачи |
| --- | --- | --- |
| Архитектор / сложный UE-разработчик | `gpt-5.6-sol`, high | C++/GAS, Animation Blueprint и retargeting, отладка Unreal, ревью архитектуры, миграции ассетов с риском потери данных. |
| Исполнитель | `gpt-5.6-terra`, medium | Изолированный gameplay-код, data assets, Unreal Python, документация, автоматические проверки, рефакторинг конкретного модуля. |
| Разведчик / QA | `gpt-5.6-luna`, low | Инвентаризация ассетов, поиск по репозиторию, анализ логов, воспроизведение ошибки, чек-лист тестов, проверка документации. |

Если в среде доступны другие названия моделей, сохраняется правило: сильная модель — только для решений с высокой неопределённостью или ценой ошибки; быстрая дешёвая — для поиска, проверки и узких преобразований.

## Параллельные дорожки

Одновременно держим не более трёх саб-агентов. Каждому назначается своя дорожка и владелец файлов.

| Дорожка | Примеры | Ограничение |
| --- | --- | --- |
| Runtime | C++/Blueprint API, GAS, input, UI, тесты | Единственный писатель в `Source/`, `Config/` и связанном модуле. |
| Character pipeline | импорт, материал, skeleton, IK Rig, retargeting, LOD/physics | Единственный писатель в конкретных `Content/_Sandbox/...` ассетах. |
| Quality / tools | Unreal Python, CI-проверки, документация, профилирование, анализ логов | Не изменяет runtime- или character-ассеты без явной передачи владения. |

`.umap`, `.uasset`, `Config/*.ini`, `*.uproject` и запуск Unreal Editor/commandlet — эксклюзивные ресурсы: с ними работает только один агент в момент времени. Параллельно с UE можно безопасно вести только read-only анализ, документацию или изолированный код вне затронутого модуля.

## Порядок работы

1. Главный агент формулирует вертикальный срез и критерии готовности.
2. `luna` быстро собирает факты: точные пути, зависимости, логи, риск конфликтов. Результат — короткий отчёт, без правок.
3. Независимые изменения делятся между `terra` и, если задача сложная, `sol`. Каждый получает уникальный набор файлов.
4. Главный агент проверяет дифф, собирает проект, запускает smoke-test/PIE и только затем коммитит и пушит.

Для задач анимации: сначала разведка и решение по retargeting, затем один агент работает в Unreal с IK/Animation assets. Нельзя одновременно открывать или сохранять те же ассеты другим агентом.

## Экономия токенов

- Передавать не всю историю, а минимальный контекст: цель, пути, текущий commit, ограничения и критерии проверки. Предпочитать `fork_turns="none"` плюс точное задание.
- Сначала поручать дешёвому агенту read-only поиск; сильную модель запускать уже с найденными фактами.
- Одна задача — один артефакт. Запрещены «сделай всё лучше» и широкие исследования без stop-condition.
- Результат саб-агента: максимум пять строк — изменённые пути, что проверено, команда проверки, риск/блокер. Не нужны промежуточные статусы и пересказ кода.
- Не дублировать анализ: один агент владеет вопросом; второй вызывается только для независимого ревью или проверки гипотезы.
- Не запускать три дорогих агента по одной и той же проблеме. Типичный состав: `sol` решает, `terra` реализует соседнюю независимую часть, `luna` проверяет.
- После каждого законченного среза коммитить. Следующим агентам передавать hash коммита, а не длинное описание прошлого.

## Шаблон задания

```text
Цель: <один измеримый результат>.
Владелец файлов: <точные пути/папка>; не изменяй ничего вне них.
Контекст: commit <hash>; <2–4 проверенных факта>.
Сделай: <конкретные действия>.
Проверка: <build/commandlet/PIE/asset validation>.
Стоп: остановись, если нужен чужой файл, интерактивная авторизация,
необратимое действие или результат зависит от другого агента.
Верни: пути, проверку, блокер — не более 5 строк.
```

## Примеры для текущего проекта

- `luna`: собрать карту зависимостей `BP_POHThirdPersonCharacter`, `RTG_Mannequin_To_POH` и `ABP_Unarmed`; перечислить минимальный набор ассетов для retargeting.
- `sol`: спроектировать и выполнить корректный retarget Animation Blueprint Manny → Prince, проверить idle/walk/run/jump на Prince skeleton.
- `terra`: подготовить Unreal Python smoke-test, который загружает Prince assets, retargeter и playable Blueprint; не открывает и не сохраняет карты.

Главный агент после этого единолично назначает `BP_POHThirdPersonCharacter` default pawn только после успешного animation smoke-test. Это не позволяет сломать уже работающие камеру, ввод и коллизии шаблона.

Базовую целостность уже созданной связки проверяет `Scripts/Development/ValidatePrinceTemplateIntegration.py`; он запускается через `UnrealEditor-Cmd -run=pythonscript` и не изменяет ассеты.
