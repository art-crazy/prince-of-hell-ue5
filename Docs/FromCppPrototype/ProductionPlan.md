# Production plan — Prince of Hell

## 0. Главный принцип

Не строим «игру на 10–15 часов» до того, как один маленький участок докажет, что главная фантазия игрока работает: **харизматичный скелет-принц, отрывающий горящую руку, побеждает в красивом тёмном бою и переселяется в новый сосуд после смерти**.

Проект проходит этапы только после измеримого гейта. Если гейт не проходит — упрощаем скоуп, а не добавляем ещё одну систему.

## 1. Цель vertical slice

Вертикальный срез — одна арена «Потухший котёл», 10–15 минут игрового времени:

- герой: бег, lock-on, лёгкая цепочка ударов, dodge, здоровье/урон;
- горящая рука: снять → бросить/атаковать → поджечь жаровню → вернуть → вставить обратно;
- смерть: огонь души выходит из тела и вселяется в соседний скелет-сосуд;
- один обычный враг, один элитный враг, один небольшой сюжетный выбор;
- один короткий диалог компаньона и несколько реактивных реплик героя;
- качественный свет, Niagara-огонь, звук, UI и стабильные 60 FPS на целевом ПК.

**Не входит в vertical slice:** открытый мир, сетевой ко-оп, дерево из десятков навыков, полноценный гигантский босс, сложная экономика, десятки видов оружия.

## 2. Фаза A — фундамент проекта

### Результат

Пустой проект UE5.8 открывается у любого разработчика из Git, собирается и запускает тестовую карту.

### Работа

1. Установить UE5.8 и создать C++ Third Person project в `C:\Users\artcr\WebstormProjects\prince-of-hell-ue5`.
2. Включить плагины: Gameplay Ability System, Enhanced Input/CommonUI, Motion Warping, Niagara, MetaSounds, PCG, StateTree, AI Perception, EQS.
3. Создать базовую структуру:
   - `Source/PrinceOfHell/` — C++-правила и тесты;
   - `Content/Core/`, `Content/Characters/`, `Content/Abilities/`, `Content/UI/`, `Content/VFX/`, `Content/Maps/`;
   - `SourceArt/` — неизменяемые исходники из Tripo/Blender.
4. Настроить Git LFS, `.gitignore`, базовый CI-check и соглашение об именах.
5. Закрепить `UE5.8` в `.uproject`, README и CI.

### Гейт A

- новый клон репозитория открывает проект без отсутствующих файлов;
- кеши UE не попадают в Git;
- `git lfs ls-files` показывает только крупные выбранные ассеты;
- test map запускается на целевой машине.

## 3. Фаза B — персонаж и ассет-пайплайн

### Результат

У героя есть экспортируемый, юридически пригодный, оптимизированный skeletal mesh с LOD и базовым ригом.

### Работа

1. После оплаты Tripo экспортировать FBX и GLB; сохранить неизменяемый оригинал в `SourceArt` через LFS.
2. Проверить файл в Blender: треугольники, UV0, normals, PBR-карты, scale, материалы, disconnected pieces.
3. Цель для LOD0: 60–90k треугольников, 1–3 материала, 4K master PBR. Создать LOD1/LOD2.
4. Проверить/починить humanoid rig; настроить IK Rig и IK Retargeter с UE5 Manny.
5. Отделить левую руку как управляемый mesh/section, добавить forearm socket и hand sockets для VFX.
6. Обновить `Docs/AssetManifest.json` фактическими измерениями и пройти validator.

### Гейт B

- mesh импортируется без warning/error;
- герой ходит, бежит, прыгает и проигрывает тестовый montage без заметного foot sliding;
- LOD переключаются без провалов силуэта;
- лицензия исходника проверена и записана.

## 4. Фаза C — боевой foundation

### Архитектура

- `AbilitySystemComponent` на герое;
- Gameplay Tags: `State.Dead`, `State.HandLaunched`, `State.LockedOn`, `Ability.Hand.Detach`, `Ability.Hand.Recall`, `Ability.Soul.Transfer`;
- Attribute Set: Health, Soul, Stamina, HandIntegrity;
- Enhanced Input contexts: exploration, combat, detached-hand, UI;
- Animation Montages + Motion Warping для атак, dodge, detach/reattach;
- события способности вызывают Niagara/MetaSound через Gameplay Cues.

### Работа

1. Реализовать locomotion, camera, lock-on, dodge и хитбоксы.
2. Реализовать один лёгкий melee combo и один enemy damage model.
3. Реализовать руку как отдельный компонент: socketed → projectile/weapon → homing recall → socketed.
4. Сделать руке ровно три функции в vertical slice: удар, свет, активация жаровни.
5. Реализовать Soul Transfer как короткую управляемую sequence с выбором ближайшего доступного сосуда.
6. Добавить debug HUD: health, tags, ability cooldown/debug state.

### Гейт C

Игрок способен завершить бой и умереть/переселиться без soft-lock, duplicate hand, сломанной камеры или рассинхрона состояний.

## 5. Фаза D — presentation и UX

### Работа

1. Niagara system `NS_Hellfire`: глаза, рука, жаровня, смерть/переселение — варианты одной базовой системы.
2. MetaSound graph: огонь, бросок руки, reattach, удар, UI feedback.
3. UMG/CommonUI: здоровье, выносливость, lock-on, интеракция; минимальный accessibility-проход (subtitles, remapping, contrast).
4. Камера: начать с проверенного third-person camera. Gameplay Camera System допускается только отдельным spike после стабильного вертикального среза.
5. Создать 20–40 коротких placeholder-линий героя с тегами событий. Финальный сценарий и озвучка — только авторские/человеческие.

### Гейт D

Срез понятен без объяснения: игрок видит, что рука отделилась, понимает её цену, замечает огонь как душу и считывает реакцию UI/звука.

## 6. Фаза E — арена и компаньон

### Работа

1. Собрать одну компактную арену из модульного окружения, Megascans/разрешённых ассетов и PCG editor-time декора.
2. Добавить один сценарный выбор: укрепить котёл или помочь псарням; сохранить Gameplay Tag/SaveGame flag.
3. Компаньон: StateTree + Perception/EQS, всего три поведения — следовать, выбрать цель, отвлечь.
4. Не пускать компаньона в traversal/hand/boss-specific механику.

### Гейт E — go/no-go

Провести 5–10 внешних плейтестов. Проект продолжает полномасштабную разработку только если:

- большинство игроков понимают руку без объяснения;
- бой читается и не ломается;
- FPS/frametime укладываются в target;
- игроки хотят увидеть следующую локацию.

Если нет — исправляем только core loop или уменьшаем игру до короткой первой части.

## 7. После vertical slice

### Порядок производства

1. Один гигантский босс как отдельный production spike: climb zone, hand grapple, 3 фазы, fallback-план без climb.
2. Система дух/сосуд в полной версии: 2–3 типа тел, не десятки вариантов.
3. Контентная цепочка: 3–4 линейные локации с повторно используемыми системами боя, выбора и VFX.
4. Катсцены/диалоги только после того, как locked core loop и локации готовы.
5. Полировка, accessibility, оптимизация, QA, демо.

### Скоуп-ограничения

- Гигантских боссов: один для первой части.
- Уникальных игровых глаголов: рука, дух/сосуд, один traversal hook; новый глагол требует удаления другого.
- Обычных врагов: 3 архетипа + элитный вариант, а не «зоопарк».
- Оружие: сигнатурная рука + одно основное melee-оружие в срезе.

## 8. Git и работа агентов

### Ветки

- `main` — только запускаемые/проверенные изменения.
- `feat/<system>` — одна законченая система на ветку.
- `spike/<technology>` — эксперименты; не вливаются без принятого решения.
- `asset/<name>` — импорт/QA конкретного ассета.

### Обязанности агентов

- Codex: C++, конфиги UE, автоматизация импорта/QA, Git, тесты, техническая документация.
- Claude: дизайн-декомпозиция, narrative/UX review, спецификации, анализ рисков; код — через тот же review/CI путь.
- Человек: финальные арт-, лицензированные, сценарные и платёжные решения; playtest и вкус.

### Definition of done для любой системы

1. есть короткая спецификация и acceptance criteria;
2. система работает на test map;
3. есть debug view/log для диагностики;
4. нет новых незафиксированных плагинов;
5. текст/код/данные закоммичены, бинарные ассеты в LFS;
6. обновлён план/manifest, если изменился контракт.

## 10. Оценка порядка величины

Для одного разработчика с агентами, без учёта покупки/ожидания ассетов: foundation + vertical slice обычно требуют **8–16 недель полной занятости**. Полная 10–15-часовая версия — уже многократно больше; её планируем только после гейта E.
